# 证据审稿与整改

适用：看稿、连续性检查、问题看板。先确定本轮范围与正文版本；普通审阅只交付意见，明确要求记录问题时才写审稿卡，明确要求改稿时才修改正文。

## 审查顺序

先核故事成立：关键人物目标、选择和结果是否有因果；时地、能力资源、知情和伏笔是否一致。再核读者体验：本章实际推进、期待兑现、高潮前铺垫和章尾承接。最后核文字：对话意图、叙述详略、重复点题、机械比喻和无功能解释。

按本书与本章挑选适用标准，不用同一题材公式评价所有作品。缺上下文或证据时明确写资料不足，不能编一个前文事实来判定矛盾。

## 问题卡

- chapterId：实际目标章；创建时 expectedChapterRevision 为读过的当前版本，后端记录证据版本。
- severity：blocking 表示影响理解、因果或连续性、必须优先处理；suggestion 为有明确收益的建议；note 为作者可自选的提示。
- category：causality / character / continuity / pacing / prose / promise。
- location：段落、场景或可辨认位置；evidence 为准确原句或明确证据，不用“整篇很 AI”。
- issue：问题是什么，造成什么具体阅读损失。
- suggestion：不越过已定情节的最小修法；涉及新事实、主线选择或结局时说明需设计决定。
- status：open / resolved / dismissed。解决或忽略仅记录处理结果，不能声称正文已自动修好。

同一问题更新原卡，不为同一发现反复建卡。正文变更后的审稿会提示证据过期；重新审查时更新真实证据和依据，不能只改状态清提示。

## 修改与回读

按原有 revise 指南优先局部 patch，保留周围原文和作者并行修改。改后回读受影响位置，检查是否改变已发生事实、角色决定、揭露顺序或后续义务；涉及这些变化时同步追踪与设定，并列出后续章影响。

报告只列有证据的发现、已做的修订及剩余问题。未做全书检查时不报告“全书无冲突”，没有运行生成式检测时也不伪造分数。
