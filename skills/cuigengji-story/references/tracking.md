# 逐章事实与连续性追踪

适用：写完一章、日更续接、修订后核对。先读 story.get 的诊断；需要写前资料时用 story.context.get 指定目标章，区分 plans 与 facts，并检查省略提示。

## 提交一章

1. 正文经 chapter.create/update 保存并回读后，取得最新真实 chapter.revision。确认本章已经写完；写一半的段落不能假装整章已完成。
2. 只记录会影响后文的实际变化：summary 为简短的已发生事件，storyTime/location 为章末时地；activeCharacterIds 使用本作品角色卡 ID，角色状态与知情仍在原生设定卡维护。故事内时间需要排序时另填 storyTimeOrder 整数（越小越早，例如闪回章给更小的值）；它只用于故事时间轴，留空就按未排序显示，不要从 storyTime 文本猜测。
3. commitments 记录交接摘要，risks 记录明确的连续性风险或未决定项；不要把检测器计数、创作过程日志塞入事实。
4. 读取最新 story.revision，以 tracking.commit 原子提交，并携带 expectedChapterRevision。冲突后保留拟稿、重读当前数据并合并，不只换版本号重送。
5. 提交成功后才继续同书下一章。正文已保存而追踪失败时明确报告，不再次生成正文。

## 四类未结事项

| kind | 用途 | 完成依据 |
| --- | --- | --- |
| foreshadow | 正文已埋下、后续要推进或回收的线索 | 有据可查的实际推进/回收 |
| promise | 章尾留下的下一章或近期强义务 | 承接章已实际回应 |
| expectation | 可分阶段兑现的长期读者期待 | 阶段回应或最终兑现 |
| constraint | 持续生效的设定、约定或信息边界 | 明确撤销或替换，而不是“写过一次” |

Thread 保留稳定 ID、标题、详情、状态、来源章节/版本和可选到期章。待埋伏笔仍放规划层；实际埋设后才附来源。追踪里的 commitments 只做本章交接概括，具体履约状态以对应 Thread 为准。不要为消除提醒而把未落实事项标 resolved。

## 修订后

正文改动会使旧追踪、来源条目和审稿证据可能失效。先比较新旧事实，再按相关人物、时间、伏笔和知情查到当前最新章节；只纠正本次受影响资料，不重读整本书。更新后的追踪必须重新依据当前正文；旧审稿的状态修改不会自动更新其证据版本。

若后续正文也受影响，列出具体章与需要处理的事实；超出授权时交付影响说明，不自动重写后文。

## 上下文预算

用“当前位置、长期约束、活跃角色、活跃伏笔、近期事实、下章承诺、风险”定位本章需要的信息。工具输出有字符预算，截断或省略表示仍有资料可按 ID 查询；零命中或当前窗口没有，不等于全书不存在。不得把后续章已写事实泄露进前面章节的写作上下文。
