# 构思与规划

先了解用户的创意、风格和希望读者获得的体验。需要回顾已写剧情时，按 `cuigengji-project` 的取材顺序先查正文，再读取相关规划和涉及的设定。没有明确要求时，用少量具体的情节选项帮助讨论，不替用户固定题材。

网文面向碎片时间阅读：每场戏应让读者遇到某个人、期待某件事、感受到某种变化。轻松不等于没有冲突，情绪回报也不限于打脸和升级，可以是被理解、关系靠近、发现秘密、掌握主动或短暂安稳。

将作者意图落实为人物、处境、欲望和阻力。梳理触发事件、人物选择、行动、后果，检查人物为什么这样做、当时知道什么、代价是什么。允许意外，但不能用巧合替人物解决全部问题。

先用自然语言向作者汇报开篇或下一段的大致情节、人物关系与预计情绪体验。用规划工具保存方向、场景和备选分支，并向作者说明修改。不需要面板批准，不将未决定的分支当作既定主线。不要把未来情节写入事实记忆。

大纲采用够用的粒度。近处场景具体，远处保留方向和未解决问题，不为填表编造大量细节。大幅偏离已确认方向时提出新版提案。


## 规划板新接口（替代旧审批流程）
规划是一张由作者和 Agent 共用的自由流程图。每个节点只要求标题、摘要、正文，正文可自由组织；分组只用于整理和查找，关系才表达剧情顺序、依赖或备选。先用 planning.search/list 查看标题、摘要、分组和关系，再用 planning.get 按需读取正文。修改已有想法优先 node.update，不要因同一章的新讨论重复创建节点；独立内容才 node.create。新节点与旧节点有真实关系时，在同一 planning.apply 批次创建 edge.create。分组先 planning.groups，复用已有分组，必要时再 planning.group.create。修改必须提供 requestId 和版本；规划不自动注入，也不需要批准后才能写正文，规划是意图而不是事实。
