# 创作工作台

「创作」页把长短篇的规划、章节蓝图、正文事实和审稿问题放在同一部作品里，与「正文」「规划」「设定」并列。它不另建项目目录，也不复制正文：所有记录都挂在当前作品的原生章节、角色卡和版本号上。

## 它解决什么

写长篇时常见的问题不是不会写，而是**写久了前后对不上**：伏笔忘了收、章尾承诺没人接、改了前面某章之后人物状态和旧意见都过期。创作工作台把这些义务显式记录下来，并绑定到具体正文版本。

它区分两件事：

- **计划**：创作简报、章节蓝图、后续义务、未完成线索——还没在正文发生。
- **事实**：正文已经写出、并经过核对的变化。

工具和界面都不会把计划当作已发生事实，也不会替你自动写正文。

## 十二个分区

| 分区 | 用途 |
| --- | --- |
| 简报与流程 | 篇幅模式（长篇/短篇）、创作阶段、创作简报：故事前提、读者期待、主角目标、核心冲突、结局方向、写作风格 |
| 章节蓝图与追踪 | 逐章记录本章意图、情节点、章尾钩子；正文写完后登记已发生事实、章末时地、活跃角色、下章承诺、连续性风险，以及作者真相/读者已知两条知识线。故事内时间可另填「故事时间序」（可选整数，越小越早），只用于故事时间轴排序 |
| 卷纲与单元 | 卷 → 剧情单元 → 章 的三层结构；单元是卷内一段完整剧情，不是一章。单元卡记录单元承诺、情绪引擎、因果入口、核心阻碍、关键选择、兑现归属与下一单元钩子；故事线矩阵标出每条线在每个单元推进到哪一步，以及"主线停摆时能否单独扛一章" |
| 故事线索 | 四类分开维护：伏笔、下章承诺、长期期待、设定约束，各有来源章节与到期章节 |
| 证据审稿 | 按严重程度与类别记录问题，必须带位置、原文证据、问题与最小修法；顶部的「审稿问题分布」按章与类别显示待处理与阻断数量 |
| 去 AI 味体检 | 对已保存正文做只读的句式检测，按段落列出候选位置并给出改写方向 |
| 节奏热力图 | 逐章记录基调（紧张/轻松/悲伤/热血/爽/甜/温馨/恐怖/压抑）与章内角色（建立/升级/转折/兑现/余波），相邻同基调会连成一段，方便看连续几章是否一个调子 |
| 角色与时间 | 两张只读投影：**角色出场矩阵**按角色 × 章显示已记录的出场，未记录与未出场分开，并统计有记录连续缺席；**故事时间轴**横轴为正文顺序、纵轴为作者填写的「故事时间序」，闪回会让折线回头。都只读事实追踪，不推断 |
| 双时间线 | 逐章并排记录「作者真相」与「读者已知」，并把作者知道、读者尚未被告知的信息差单独列出；信息差只比较两栏完全相同的中文条目，不推断未记录的信息 |
| 文风对照 | 写下目标平均句长（按每句可见字数）、对白占比、视角、时态、用词与要避免的东西；右侧用正文实测值逐章对照，差值带正负号 |
| 拆文库与对标 | 导入本机 `拆文库/书名` 文件夹，保存为本书内的对标副本：拆文报告、文风档案、节奏索引、情绪模块与逐章摘要；按章并排对照参考书与本书的基调，不把参考书情节当本书事实 |
| AI 上下文 | 按目标章与字数预算预览续写时会带入哪些材料，以及哪些被省略、为什么 |

顶部进度显示「已有蓝图 / 正文事实已追踪 / 到期未核对 / 待处理阻断问题」，点数字旁的入口可直接跳转。

## 去 AI 味体检怎么用

这一页只报告候选位置，**不给分数**。它按句式和段落规则标出可能读起来像机器的地方，例如「不是 A，而是 B」式对比、章尾总结体、碎句号、套词聚集、解释链过密。每条都带行号和原文摘录，点一下跳到正文那一句。

命中不等于必须改：有些长句、反复和短句是作者故意写的。反过来，零命中也不代表故事成立——它只检查表达层，管不了人物动机、因果和节奏。所以这一页永远显示「命中只是候选，不是评分」。

方法来源：句式规则移植自 Oh Story 的 `story-deslop` 检测脚本，归属与许可见 `THIRD_PARTY_NOTICES.md`。

## 拆文库与对标怎么用

先在 `拆文库/书名/` 里准备分析成果（目录名与文件名可按实际调整，导入时按以下文件读取）：

```text
拆文库/书名/
├── _meta.json          可选，{"title":"书名"}
├── 拆文报告.md          报告与可借鉴写法
├── 文风.md              语感、句长、对白比例与锚点
├── 剧情/节奏.md         节奏索引
├── 剧情/情绪模块.md     情绪模块
├── 章节/第1章_摘要.md   每章一份；可写「基调：紧张」「角色定位：建立」「字数：2400」
└── 角色/、设定/         用于统计角色与设定文件数量
```

在「拆文库与对标」分区填写该文件夹的绝对路径，点「导入对标书」。导入只读原目录，保存的是本书内的一份副本；删除对标也只删除这份副本。导入后可以看逐章摘要、文风档案、节奏与情绪模块，并在「节奏对照」里按章序对比参考书与本书的基调。参考书用于借鉴节奏与写法，不会把它的情节、人物或设定当成本书事实。

## 版本绑定

每条事实追踪、审稿意见、章节节奏都记录它依据的正文版本。**正文改动后，旧记录会被标记为「来源已变化」**，需要你重新核对当前正文再更新；只改状态、只换版本号都不会消除提示。

界面顶部的「创作 vN」是本页数据的版本号，与正文版本分开。两个人同时编辑时，保存会检查版本：旧页面不会覆盖新数据，冲突时会保留你的本地草稿并提示先核对。

## 给 AI 的入口

Agent 通过 `cuigengji_story` 读写同一份数据（`story.get` / `story.apply` / `story.context.get`），作者在界面上的修改和 AI 的修改落在一起。`story.context.get` 只返回目标章及之前的资料，并按字符预算截断，明确报告被省略的条目及原因，不会把后面的剧情提前泄露给前面章节的写作。`story.detect` 做只读的句式检测，返回带行号的候选与分类计数，不评分也不改正文。

写作方法按阶段加载，不常驻占用上下文：`cuigengji_guidance` 的 `story` 是路由，`story-long`、`story-short`、`story-outline`、`story-tracking`、`story-review`、`story-deslop` 分别是长篇、短篇、章蓝图、追踪、审稿、精修，`story-operations` 是完整操作字段。

## 旧作品与数据安全

- 打开旧作品不会自动写入创作数据；第一次保存时才创建。
- 导出整本作品会带上创作资料；按章复用时会重映射章节、角色引用，并去掉未选中的部分。
- 创作资料随作品备份与恢复，不进入仓库源码目录。
