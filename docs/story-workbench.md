# 创作工作台

「创作」页把长短篇的规划、章节蓝图、正文事实和审稿问题放在同一部作品里，与「正文」「规划」「设定」并列。它不另建项目目录，也不复制正文：所有记录都挂在当前作品的原生章节、角色卡和版本号上。

## 它解决什么

写长篇时常见的问题不是不会写，而是**写久了前后对不上**：伏笔忘了收、章尾承诺没人接、改了前面某章之后人物状态和旧意见都过期。创作工作台把这些义务显式记录下来，并绑定到具体正文版本。

它区分两件事：

- **计划**：创作简报、章节蓝图、后续义务、未完成线索——还没在正文发生。
- **事实**：正文已经写出、并经过核对的变化。

工具和界面都不会把计划当作已发生事实，也不会替你自动写正文。

## 四个分区

| 分区 | 用途 |
| --- | --- |
| 简报与流程 | 篇幅模式（长篇/短篇）、创作阶段、创作简报：故事前提、读者期待、主角目标、核心冲突、结局方向、写作风格 |
| 章节蓝图与追踪 | 逐章记录本章意图、情节点、章尾钩子；正文写完后登记已发生事实、章末时地、活跃角色、下章承诺与连续性风险 |
| 故事线索 | 四类分开维护：伏笔、下章承诺、长期期待、设定约束，各有来源章节与到期章节 |
| 证据审稿 | 按严重程度与类别记录问题，必须带位置、原文证据、问题与最小修法 |

顶部进度显示「已有蓝图 / 正文事实已追踪 / 到期未核对 / 待处理阻断问题」，点数字旁的入口可直接跳转。

## 版本绑定

每条事实追踪和审稿意见都记录它依据的正文版本。**正文改动后，旧记录会被标记为「来源已变化」**，需要你重新核对当前正文再更新；只改状态、只换版本号都不会消除提示。

界面顶部的「创作 vN」是本页数据的版本号，与正文版本分开。两个人同时编辑时，保存会检查版本：旧页面不会覆盖新数据，冲突时会保留你的本地草稿并提示先核对。

## 给 AI 的入口

Agent 通过 `cuigengji_story` 读写同一份数据（`story.get` / `story.apply` / `story.context.get`），作者在界面上的修改和 AI 的修改落在一起。`story.context.get` 只返回目标章及之前的资料，并按字符预算截断，明确报告被省略的条目及原因，不会把后面的剧情提前泄露给前面章节的写作。

写作方法按阶段加载，不常驻占用上下文：`cuigengji_guidance` 的 `story` 是路由，`story-long`、`story-short`、`story-outline`、`story-tracking`、`story-review`、`story-deslop` 分别是长篇、短篇、章蓝图、追踪、审稿、精修，`story-operations` 是完整操作字段。

## 旧作品与数据安全

- 打开旧作品不会自动写入创作数据；第一次保存时才创建。
- 导出整本作品会带上创作资料；按章复用时会重映射章节、角色引用，并去掉未选中的部分。
- 创作资料随作品备份与恢复，不进入仓库源码目录。
