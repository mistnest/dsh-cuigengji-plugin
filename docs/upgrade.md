# 更新与数据迁移

当前正式版 **0.5.1**，最低宿主要求保持 DSH `>=0.2.0-rc.2`；本次实际验收 Windows 桌面版 **0.2.1-rc.5** 及 **0.2.2-alpha.2 官方标签源码构建桌面**。alpha.2 暂无官方 Windows 成品安装包；具体范围见[更新记录](CHANGELOG.md)。允许安装的范围和实际测试版本分开记录，未来宿主接口变化仍需具体排查。

安装或更新使用 `dsh-cuigengji-plugin@0.5.1`，也可使用 [Release 成品包](https://github.com/mistnest/dsh-cuigengji-plugin/releases/tag/v0.5.1)。普通用户无需 Git、Node.js 或源码构建。将 [Agent 安装指南](agent-installation.md)交给负责更新的 AI，由它保留配置、重启并验收；已有作品无需重新导入。

## 0.5.0 升级到 0.5.1

存储布局仍为版本 5，保留原配置、作品目录及已有数据，无需重新导入。此补丁兼容文件开头的 UTF-8 BOM，不需要 Agent 手工重存小说文件；确实损坏的 JSON 会保留错误路径和解析原因，不能删除文件来跳过校验。新会话的写作指引默认开启，已有会话明确关闭的选择继续保留。

本次发布验收覆盖上一公开版 0.5.0 的无 Git 升级、完整逻辑数据保留，以及带 BOM 预设在真实桌面升级后恢复写作。

## 0.4.x 升级到 0.5.x

0.5.x 使用**存储布局版本 5**：正文按卷、设定按文件夹、规划按画布和文件夹保存，规划正文拆为独立文件。界面里的组织方式与物理目录对应，工具和历史引用继续使用原业务 ID。不要在文件管理器里手工移动、重命名或编辑这些受管理文件。

插件启动时自动完成备份、迁移和校验。0.4.5 的布局 4 及更早的布局 1–3 都有迁移路径。原作品、回收站、正文历史、规划页及连线、设定与来源、预设、导入原件和请求记录继续保留；旧会话目标转换为作品库级访问，并记住原先选择的作品。

0.4.5 实际写入的分文件工作库升级已在 0.5.0 发布验收；本次继续验收 0.4.1 旧安装名升级。历史单文件库迁移由合成旧库回归覆盖，不把它与 0.4.5 的布局 4 混为一谈。

旧安装名 `dsh-cuigengji` 需要先按[名称迁移指南](package-name-migration.md)转接启用项和配置，不同时启用两个包。重复安装同一个无 ref 的 GitHub 地址可能沿用旧提交；升级优先使用精确版本或固定 Release 地址。

## 启动时发生什么

1. 读取当前数据根：插件配置 `dataRoot` > `CUIGENGJI_DATA_ROOT` > 系统默认目录。
2. 在数据根旁建立完整原始快照，包括历史、导入原件和作者放入的额外文件；不复制锁等瞬态文件。
3. 在同一锁内恢复挂起的文件事务，迁移旧布局，保持业务 ID、内容与引用。
4. 比较完整逻辑工作库，检查正文哈希、历史、规划、设定关系与会话目标，通过后才开放普通工具。

状态保存在 `runtime/upgrade.json`。同版本重复启动复用已完成的备份，不反复迁移。插件不会借迁移把正文或旧设定自动塞进 AI 的上下文。

## Agent 必须核对

重启后先调用 `cuigengji_maintenance`：

```json
{"action":"status","args":{}}
```

再使用更新前记下的实际目录与作品 ID：

```json
{"action":"verify","args":{"expectedVersion":"0.5.1","expectedDataRoot":"C:\\Users\\用户\\AppData\\Local\\cuigengji","expectedNovelIds":[]}}
```

只有 `status.status=ready` 且 `verify.verified=true`，实际版本、数据根和原作品均正确，才报告完成。安装器显示成功或磁盘包已更新，不能代替重启后的核对。

失败时保留 `failedStage`、错误代码、数据根和 `backupPath`。不要创建空库、删除索引或重新导入来掩盖错误；可完整重启继续恢复。升级快照在数据根旁 `.cuigengji-upgrade-backups/<数据根摘要>/<本次升级>/data`，旁边的 `manifest.json` 包含逐文件校验值。

## 切换作品库与恢复

正常更换位置使用「设置 → 数据与备份 → 作品库目录」。可以打开已有库、新建空库，或迁移当前库到空目录。迁移复制已校验快照，核对内容后才切换；原目录和备份继续保留。新旧目录不能相同或互相嵌套，写作和数据操作进行中不能切换。

回退代码不等于回退数据格式。**0.4.x 不能直接打开已经迁移为布局 5 的目录。**确需回退时先停止 DSH，保存升级后新增内容，再校验升级前快照，将其复制到新的恢复目录并用对应旧包验证；原库和快照不覆盖、不删除。恢复范围及升级后内容的处理须经作者确认。

DSH 聊天、附件、账号配置和浏览器未保存草稿由宿主管理，不属于催更姬作品快照。完整功能变化见[更新记录](CHANGELOG.md)。
