# 更新记录

## 0.4.5 放宽 DSH 版本范围

- 最低宿主要求改为 DSH `>=0.2.0-rc.2`，宿主与 peer 依赖声明保持一致；后续 DSH 正式版和预发布版不再因未列入白名单而被拒绝安装。
- 安装允许范围与实际验收记录分开维护，已实际验收 Windows 桌面版 0.2.1-rc.2 和 0.2.0-rc.2；未来版本允许安装不代表已经逐一测试。遇到真实接口变化再按受影响能力处理。
- 正文、规划、设定、预设、工具和存储格式沿用公开 0.4.3 系列；新版 DSH 的实际工作台运行、无 Git 安装、0.4.3 / 0.4.4 升级和旧包名迁移分别验收，保留原配置及小说工作数据。
- 0.4.4 已经公开，安装包保持原样；本次声明调整以新补丁版本发布，避免同版本出现不同包内容。

## 0.4.4 新版 DSH 兼容修补

- 支持 DSH Windows 桌面版 0.2.1-rc.2，保留 0.2.0-rc.2 兼容；修复原 0.4.3 因宿主版本声明被新版插件管理器拒绝安装的问题。
- 安装维护工具兼容新版桌面内置包管理器的位置，继续使用 DSH 原生安装流程，无需用户额外安装 Git、Node.js 或编译源码。
- 发布验收使用各版桌面自带的包管理器和运行时，覆盖新版实际工作台、接口、工具与 Skill，以及旧宿主 0.4.3 到新版宿主 0.4.4 的完整数据保留。
- 此版本仅基于公开 0.4.3 做兼容修补，正文、规划、设定、预设和存储格式沿用原有行为；0.5 开发功能不在本次更新中。已有用户保留原数据目录更新即可，无需重新导入作品。

## 0.4.3 固定发布与验收流程

- 维护者通过统一发布入口完成预检、打包、GitHub 发布、npm 可信发布、安装与升级验收及市场条目同步，减少渠道版本和安装包不一致的问题。
- 发布前在临时 Windows DSH 环境验证无 Git 安装，以及上一公开版和旧包名版本的升级、原配置和合成作品数据保留。
- GitHub 与 npm 复用同一份归档；新增断点续跑、版本与提交绑定、资产哈希检查和发布报告，不替换已公开的同版本安装包。
- npm 只有在精确版本、归档、完整性、版本标签和原生安装均核对通过后才算可用，占位包与命令返回成功不作为验收结果。
- 将维护者发布流程与普通用户的安装、迁移 Skill 分开，发布权限通过 GitHub Actions 的可信授权处理，交接资料不保存账号凭据。

## 0.4.2 统一名称与作品回收站

- GitHub 仓库、npm 包和市场显示名统一为 `dsh-cuigengji-plugin`，界面仍显示“催更姬”；增加搜索关键词，安装文档优先面向 Windows 桌面用户。
- 旧 `dsh-cuigengji` 安装由名称迁移工具转接启用项和自定义配置，保留数据根、内部 ID、工具名、草稿及历史；原配置先备份，去重避免两份插件同时加载，新版验收后才移除旧依赖。
- 首页每本作品右侧直接进入删除确认，删除后整本作品进入回收站；支持恢复与永久删除，保留正文、设定、规划、历史和引用。AI 正在使用作品时阻止回收，回收作品不参与正常读取和写作。
- 首页移除底部功能宣传文字，将作品回收站入口放在右下方；导入导出选择与备份兼容作品回收状态。
- 固定源码、同一份安装包、npm/GitHub Release/市场的维护分工，补充安装与升级 Agent 指南，保留无 Git 的成品包入口。

## 0.4.1 GitHub 地址直接安装

- 发布改用显式 `pack:release`，新增产物一致性检查与 GitHub CI，避免提交源码后遗漏编译文件。
- 补充“包名或地址”和 npm“安装源”的区别，保留成品包安装和原有自动备份、迁移与校验。
- 修复写作预设自己保存后误报“有更新”的提示；真正的并发更新仍会提醒，并保留当前未保存草稿。

## 0.4.0 安全更新与可维护工作库

- 新增不要求绑定小说的 `cuigengji_maintenance` 工具，负责更新后查询实际加载版本、数据根、迁移阶段、作品计数和完整性校验结果；失败时锁住普通小说操作，避免生成空库或丢失数据。

- 新增按作品、正文、设定、规划页、预设或完整工作库导入导出；统一文件识别、范围、关联收集、冲突预览、备份与原子写入，兼容旧备份与酒馆资料。
- 数据按书名建目录，章节、设定与规划页使用可读名称加短 ID；改名、重名、非法字符、自存文件避让和中断恢复均保留完整内容与内部引用。
- 重排欢迎页、作品管理、预设、批量操作、设置和关于页面；常用首页与刷新常驻，作者交流和支持信息有独立关于入口。
- 公开源码继续不包含私人作品与真实工作数据；迁移备份放在数据根旁的隐藏目录，不进入 Git 仓库。
